## 모델은 결과물과 사용량을 함께 바꾼다

모델을 고르는 기준은 이름의 숫자보다 맡길 일이다. 복잡한 자료를 판단해 완성된 문서를 만드는 일과,
정해진 형식으로 많은 항목을 분류하는 일은 필요한 추론 수준이 다르다. 결과가 부족하면 더 깊은
설정을 시험하고, 단순 반복 작업의 사용량이 크면 작은 모델과 좁은 범위를 먼저 검토한다.

**2026년 10월 23일 확인한 공식 문서**는 복잡한 작업에 GPT-6.1 Sol, 가장 어려운 작업에
GPT-6 Astra, 명확하고 반복적인 작업에 GPT-6 Luna를 안내한다. GPT-6 Sol과 GPT-5.6 계열도
롤아웃 중에 남아 있으므로 목록에 보이는 모델과 조직이 허용한 모델을 먼저 확인한다.

ChatGPT Work와 Codex는 가격·크레딧·사용 한도를 공유한다. API 키로 사용하는 경우에는 별도
API 요금이 적용된다. API의 토큰 가격을 구독에 포함된 작업 횟수로 환산해서는 안 된다.

## Astra · GPT-6.1 Sol · Luna의 선택 기준

| 모델 | 공식 문서의 용도 | 업무 예시 |
|---|---|---|
| **GPT-6 Astra** | 코드·앱·리서치를 넘나드는 가장 어려운 전체 작업 | 여러 시스템을 확인하고 판단해 템플릿에 맞는 최종 보고서 준비 |
| **GPT-6.1 Sol** | Astra에 가까운 성능을 더 낮은 비용으로 제공하는 복잡한 작업 | 문서·앱을 오가는 장시간 작업과 반복 보고서 작성 |
| **GPT-6 Luna** | 범위와 성공 기준이 분명한 대량 작업 | 추출·분류·변환·정형 요약 |

GPT-6.1 Sol의 출시 롤아웃은 Plus·Pro·Business·Enterprise·Edu를 대상으로 한다. Free·Go는
출시 대상에 포함되지 않는다. Enterprise·Edu에서는 기본으로 꺼져 있어 관리자가 켜야 한다.
Free·Go는 데스크톱 앱에서 제공되는 GPT-6 Luna를 확인한다. 모델을 선택하는 것만으로
워크스페이스 권한이나 이용 자격이 생기지는 않는다.

GPT-6.1 Sol·GPT-6 Sol·GPT-6 Luna는 Work와 Codex에 제공되며 일반 Chat의 모델 목록과는
다르다. 모든 모델이 모든 화면에 동시에 나타난다고 기대하지 않는다.

## Power, 추론 수준, 실행 속도를 구분한다

입력창 아래의 모델 컨트롤에서 계정에 제공되는 기본 **Power** 설정으로 시작한다.
**Smarter**는 더 깊은 추론, **Faster**는 더 빠르고 비용이 낮은 작업 쪽으로 조정한다.
특정 모델·추론 수준·속도는 **Advanced**에서 고른다. 현재 문서는 Power의 모델과 기본값이
플랜·클라이언트·워크스페이스 설정·롤아웃에 따라 다르다고 설명하므로 고정된 모델로 외우지 않는다.

| 설정 | 무엇을 바꾸나 | 판단 기준 |
|---|---|---|
| Light / Low, Medium, High, Extra High | 한 작업을 얼마나 깊게 추론할지 | 기본값에서 시작하고 결과에 필요한 만큼 올린다 |
| Max | 선택한 모델이 한 문제를 더 오래 추론 | 속도보다 깊이가 중요한 어려운 문제 |
| Ultra | 서브에이전트(subagents)로 작업의 여러 부분을 병렬 처리 | 의미 있는 독립 작업으로 나눌 수 있는 큰 일 |
| Fast / Ultrafast | 지원되는 모델의 출력 속도 | 별도 사용량 배수와 이용 자격을 먼저 확인 |

공식 문서는 Luna는 High, Astra는 Light에서 시작하도록 안내한다. GPT-6.1 Sol은 현재
클라이언트의 기본 추론 수준에서 조정한다. 모델 세대마다 추론 설정이 정확히 대응하지는 않는다.
GPT-6 Luna는 Max까지 지원하고 Ultra는 지원하지 않는다. 대부분의 작업에는 Max·Ultra가 필요 없다.

Ultrafast는 GPT-6 Astra와 GPT-6.1 Sol을 지원하며 Pro $500과 자격을 갖춘 Enterprise·Edu에
제공된다. Enterprise에서는 기본으로 꺼져 있고 관리자가 접근을 허용해야 한다. 다른 셀프서비스
플랜에서 크레딧을 구매했다고 이용 자격이 생기지는 않는다.

## 은퇴 모델은 저장된 설정까지 정리한다

GPT-5.5는 **2026년 10월 14일 정오 PDT**에 ChatGPT 로그인 방식의 Codex에서 은퇴했다.
공식 주간 업데이트는 ChatGPT·Work·Codex 전반의 은퇴를 안내한다. API와 API 키로 인증한
Codex 세션은 이 은퇴의 영향을 받지 않는다.

| 저장된 모델 | 현재 공식 문서가 안내하는 전환 |
|---|---|
| `gpt-5.5` | Plus·Pro·Business·Enterprise·Edu는 제공되는 `gpt-6.1-sol`, Free·Go는 데스크톱의 `gpt-6-luna` |
| `gpt-5.4` | 8월 31일 은퇴. 계정과 클라이언트에서 제공되는 `gpt-6-sol` |
| `gpt-5.4-mini` | 8월 31일 은퇴. 제공되는 `gpt-6-luna`. Enterprise·Edu는 관리자 활성화 필요 |
| `gpt-5.3-codex-spark` | 9월 14일 은퇴. 현재 사용 가능한 모델로 변경 |

워크스페이스 기본값, 저장된 모델 설정, 관리형 설정, 커스텀 에이전트와 **예약 작업(scheduled
tasks)**을 함께 점검한다. 모델 이름만 바꾼 뒤 끝내지 말고, 대표 작업을 실행해 출력 형식·품질·
사용량을 확인한다. `gpt-5.2`·`gpt-5.3-codex` 같은 더 오래된 참조도 정리한다.

```text
[워크플로명]에서 저장한 모델과 예약 작업 설정을 확인해 주세요.
은퇴한 모델이 있으면 현재 계정에서 제공되는 대안을 제안해 주세요.
설정은 아직 바꾸지 말고, 전환 후 비교할 대표 입력과 검토 기준을 함께 적어 주세요.
```

## 크레딧 요율과 구독 한도는 다르다

토큰(tokens)은 모델이 읽고 쓰는 정보의 작은 단위다. 프롬프트·파일·대화 기록·도구 결과·응답이
모두 토큰을 쓴다. 크레딧(credits)은 크레딧 기반 플랜의 해당 사용량을 지불하는 단위다.
모델·컨텍스트·추론·도구·검색·캐시에 따라 사용량이 달라져 프롬프트 길이만으로 예상하기 어렵다.

아래는 확인일의 **Standard 속도, 100만 토큰당 크레딧**이다. 구독에 포함된 메시지 횟수가 아니다.

| 모델 | 입력 | 캐시된 입력 | 출력 |
|---|---|---|---|
| GPT-6 Astra | 250 | 25 | 1,250 |
| GPT-6.1 Sol | 50 | 2.5 | 250 |
| GPT-6 Sol | 50 | 5 | 250 |
| GPT-6 Luna | 2.5 | 0.25 | 12.5 |

같은 모델의 Standard 대비 Fast는 구독 포함 사용량을 2.5배, 구매 크레딧과 Enterprise
종량 사용량을 2배로 소비한다. Ultrafast는 각각 8배와 6배다. 이미지 생성은 화질·크기에 따라
이미지 생성이 없는 유사한 턴보다 포함 한도를 평균 3~5배 빠르게 쓴다.

실제 한도와 초기화 시점은 사용량 대시보드에서 확인한다. 작업 범위와 자료가 다르면 비슷한
요청도 사용량이 달라진다. 비용이 작아도 결과가 틀리면 다시 작업해야 하므로 완성된 결과물의
가치를 함께 본다.

**범위가 없는 요청**인 “우리 시장을 전부 조사해 주세요”를 다음처럼 좁힌다.

```text
[제품 카테고리]의 시장 상황을 정리해 주세요.
첨부 리포트 2개와 [경쟁사 3곳]의 공식 요금 페이지만 쓰세요.
최근 12개월과 상위 5개 항목으로 제한하고, 1페이지 요약과 비교표를 주세요.
주장마다 출처를 붙이고, 확인하지 못한 항목은 표시하세요. 발송 전 초안에서 멈추세요.
```

## 정리

- 어려운 전체 작업에는 Astra, 비용을 함께 보는 복잡한 작업에는 GPT-6.1 Sol, 정형 반복에는 Luna를 검토한다.
- Power의 기본 모델은 고정하지 않는다. 추론 수준과 속도 설정은 서로 다른 선택이다.
- 은퇴 모델은 이미 지난 일정으로 다루고, 예약 작업과 저장된 기본값까지 전환한다.
- Standard 크레딧 요율과 구독 포함 한도, API 과금은 구분한다.
- 기능은 플랜·플랫폼·지역·롤아웃·워크스페이스 설정에 따라 다르다. 현재 모델 목록과 사용량 화면을 확인한다.

다음 섹션에서는 실제 결과물인 문서·발표자료·스프레드시트를 만들고 검토하는 방법을 다룬다.
