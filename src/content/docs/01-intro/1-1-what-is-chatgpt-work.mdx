## 질문에 답하는 AI에서, 일을 끝내는 AI로

월요일 오전에 이런 요청을 받는다. "지난 분기 고객 인터뷰 노트 12개와 설문 결과
스프레드시트를 보고, 목요일 제품 리더십 회의에 쓸 8장 발표자료를 만들어 주세요."
자료는 여러 곳에 흩어져 있고, 정리 기준은 아직 없고, 결과물은 남이 열어 볼 수 있는
파일이어야 한다. 이럴 때 필요한 것은 잘 쓰인 답변 한 문단이 아니라 검토할 수 있는
파일 한 개다.

ChatGPT Work는 바로 이 지점을 겨냥한 ChatGPT의 작업 방식이다. 공식 문서는 이를
"실제 업무를 ChatGPT에 위임하는 방법(a way to delegate real work to ChatGPT)"이라고
설명한다. 답이나 설명, 짧은 초안이 필요할 때는 Chat을 쓰고, 브리프·발표자료·분석·정기
업데이트·워크플로처럼 **완료 기준이 분명한 결과물**이 필요할 때 ChatGPT Work를 쓴다.

한 가지 먼저 정리해 둘 것이 있다. ChatGPT Work는 **별도 앱이 아니다.** ChatGPT
데스크톱 앱(macOS·Windows), 웹, 모바일 안에서 Work로 전환해 쓰는 모드다. 그래서
"ChatGPT Work를 설치한다"는 표현은 정확하지 않고, "ChatGPT를 열고 Work로 바꾼다"가
맞는 표현이다.

## Chat · ChatGPT Work · Codex, 무엇이 다른가

ChatGPT에는 세 가지 사용 방식이 있다. 공식 문서의 구분은 다음과 같다.

| 선택 | 이럴 때 쓴다 | 예시 |
|---|---|---|
| **Chat** | ChatGPT와 주고받으며 무언가를 풀어 나가고 싶을 때 | 질문하기, 웹 검색, 브레인스토밍, 메시지 초안 쓰기, 선택지 비교 |
| **ChatGPT Work** | 결과물을 정의하고 검토 가능한 산출물을 받고 싶을 때 | 발표자료 만들기, 파일 분석, 보고서 초안, 프로젝트 계획 수립 |
| **Codex** | 개발자 도구를 쓰고 기술적 세부를 보고 싶을 때 | 코드 디버깅, 테스트 실행, PR 리뷰, 기능 구현 |

핵심 기준은 "무엇을 받고 싶은가"다. 대화가 목적이면 Chat, 결과물이 목적이면 Work다.
큰 작업이라도 아직 방향이 흐릿하다면 Chat에서 문제를 정리한 다음 Work로 넘기는 편이
낫다.

Codex는 지금도 개발자용 뷰로 별도 존재한다. 기능은 ChatGPT Work와 상당 부분 겹치지만
화면이 다르다. 데스크톱 앱에서 둘을 비교하면 이렇다.

| 차이 | 데스크톱 앱의 ChatGPT | 데스크톱 앱의 Codex |
|---|---|---|
| 시작 위치 | **ChatGPT** 선택 후 **Work** 로 전환 | 제품 선택기에서 **Codex** 선택 |
| 보이는 대화 | 웹·모바일의 Chat 대화와 ChatGPT Work 대화 | Codex 대화와 개발 프로젝트 중심 |
| 기술 세부 | Git이나 셸 명령 같은 기술 세부를 감춤 | diff·리뷰 뷰 등 개발자 세부를 노출 |
| 표현 방식 | 비기술적 언어와 완성된 결과물을 선호 | 기술적·구현적 세부를 포함할 수 있음 |
| PR 패널 | ChatGPT Work에서는 제공되지 않음 | 활성화된 경우 사용 가능 |

공식 문서는 "Codex를 비개발 업무에 써 왔다면 계속 Codex를 써도 되고, ChatGPT Work로
옮겨도 된다"고 안내한다. 같은 핵심 기능을 일상 업무에 맞춘 화면으로 제공하는 것이
ChatGPT Work다.

## ChatGPT Work가 실제로 하는 일

ChatGPT Work는 작업을 계획하고, 컨텍스트를 모으고, 도구를 쓰고, 검토할 수 있는 결과까지
끌고 간다. 공식 문서가 정리한 아홉 가지 유형은 다음과 같다.

- **정보를 조사하고 분석한다.** 웹을 검색하고 웹사이트를 열어 보며 출처를 비교하고,
  파일을 읽고 데이터를 분석해 결과를 요약한다.
- **내 파일과 도구를 쓴다.** 업로드한 파일, 프로젝트(projects), 메모리(memories),
  ChatGPT 라이브러리, 설치한 플러그인(plugins)을 가져와 쓴다.
- **완성된 파일을 만든다.** 문서·발표자료·스프레드시트·PDF를 만들고 다듬는다. 결과를
  확인하고 구체적인 수정을 요청한 뒤 완성된 파일을 내려받는다.
- **시각적·상호작용 결과물을 만든다.** 이미지를 생성하거나 편집하고, 상호작용
  시각화(visualizations)를 만들고, Sites로 웹사이트와 앱을 만들어 공유한다.
- **웹사이트와 앱을 넘나들며 일한다.** 내장 브라우저(browser)로 조사하고 조작한다.
  데스크톱 앱에서는 Chrome 확장, Computer Use, Appshot도 쓸 수 있다.
- **코드를 실행하고 기술 작업을 검토한다.** 코드와 셸 명령을 실행하고 데이터와 파일을
  살펴본다. 비개발자에게는 자주 필요한 기능이 아니다.
- **긴 작업을 위임하고 이어 간다.** 독립적인 일을 서브에이전트(subagents)로 나누고
  진행 상황을 따라가며, 장시간 작업(long-running work)을 계속 살려 둔다.
- **쓸 만한 워크플로를 반복한다.** 반복 업무에 예약 작업(scheduled tasks)을 걸고,
  스킬(skills)로 같은 절차를 재사용한다.
- **말로 작업을 진행한다.** 지원되는 플랜의 데스크톱 앱에서 ChatGPT Voice로 작업을
  시작하고 진행을 확인하고 방향을 바꾼다.

이 흐름을 한 장으로 보면 다음과 같다.

```text
┌──────────────┐
│  목표 전달   │  "무엇이 끝난 상태인가"를 문장으로
└──────┬───────┘
       │
┌──────▼───────┐   파일 · 플러그인 · 웹 · 프로젝트
│ 컨텍스트 수집 │ ◀────────────────────────────────
└──────┬───────┘
       │
┌──────▼───────┐   중간 질문 · 승인 요청
│  계획과 실행  │ ─────────────────▶  사용자 개입
└──────┬───────┘
       │
┌──────▼───────┐
│ 검토용 결과물 │  문서 · 슬라이드 · 시트 · 사이트
└──────────────┘
```

화면으로 보면 대화창 옆에 결과물과 진행 상황이 함께 놓인다.

주목할 점은 대화가 곧 결과물이 되는 게 아니라, 대화 옆에 **별도의 산출물**이 쌓인다는
것이다. 그래서 Work에서는 "답이 마음에 드는가"보다 "파일을 열어 봤는가"가 더 중요한
질문이 된다.

## 언제 등장했고, 어디서 쓸 수 있나

ChatGPT Work는 공식 주간 업데이트 문서 기준으로 **2026년 7월 6~10일 주차**에 발표됐다.
GPT-5.6 기반으로 목표를 단계로 쪼개 몇 시간 동안 작업할 수 있고, 그동안 사용자는 진행
상황을 따라가며 질문에 답하고 방향을 바꾸고 중요한 행동을 승인한다.

같은 주 **7월 9일에는 Codex 앱이 ChatGPT 데스크톱 앱으로 통합**됐다. Codex는 통합된 앱
안에서 전용 코딩 경험으로 남고, 그 옆에 ChatGPT의 Chat과 Work가 함께 놓인 구조다.
통합된 데스크톱 앱은 Free를 포함한 모든 ChatGPT 플랜에서 전 세계에 제공된다.

가용성은 플랜과 플랫폼에 따라 다르다. 제품 페이지의 표기는 다음과 같다.
**macOS·Windows 데스크톱에서는 모든 플랜에, 웹과 모바일에서는 Plus·Pro·Business·
Enterprise·Edu에 제공된다.** 여기에 더해 공식 문서는 기능 전반에 대해 "기능은 플랜,
플랫폼, 지역, 롤아웃, 워크스페이스 설정에 따라 달라진다"고 안내한다. 워크스페이스
관리자는 ChatGPT Work 자체와 플러그인, 브라우저 사용, 네트워크 접근을 제어할 수 있다.
이 사이트에서 설명하는 화면이 보이지 않는다면 대개 이 다섯 가지 중 하나가 원인이다.

## 해보기: 첫 요청을 다듬는 3단계

공식 문서는 "동료에게 부탁하듯 쓰라"고 권한다. 첫 프롬프트는 출발점일 뿐이므로
완벽하지 않아도 된다. 같은 요청을 세 단계로 다듬어 보자.

**1단계 — 단순하게 시작한다.**

```text
새 고객 피드백 프로세스를 다루는 30분짜리 팀 미팅을 기획해 주세요.
```

**2단계 — 답을 바꾸는 맥락을 더한다.**

```text
새 고객 피드백 프로세스를 다루는 30분짜리 팀 미팅을 기획해 주세요.
대상은 이 프로세스를 처음 접하는 고객지원팀입니다.
질의응답 5분을 포함하고, 명확한 다음 할 일로 마무리해 주세요.
```

**3단계 — 필요한 형식을 지정한다.**

```text
이 프로세스를 처음 접하는 고객지원팀을 위한 30분 미팅 아젠다를 만들어 주세요.
질의응답 5분을 포함하고, 명확한 다음 할 일로 마무리하고,
캘린더 초대장에 그대로 붙여 넣을 수 있는 형식으로 정리해 주세요.
```

Work에 맡길 만한 작업이라면 여기에 자료와 완료 기준을 더한다. 공식 문서가 제시한
나쁜 예와 좋은 예의 대비가 분명하다.

**나쁜 예:**

```text
고객 리서치에 대한 발표자료를 만들어 주세요.
```

**좋은 예:**

```text
첨부한 인터뷰 노트와 설문 결과를 검토해 주세요.
제품 리더십 회의용 8장 발표자료를 만들어 주세요.
가장 자주 나온 고객 문제 세 가지에 집중하고, 근거를 함께 담고,
발견 사항과 제안을 분리하고, 근거가 약한 주장은 표시해 주세요.
원본 문서는 [자료 위치]에 있습니다.
최종본으로 취급하기 전에 검토용 초안을 먼저 보여 주세요.
```

차이는 길이가 아니라 **결과물·자료·제약·완료 기준·중단 지점**이 들어 있는지다.

## 흔한 오해 세 가지

| 오해 | 실제 |
|---|---|
| ChatGPT Work는 별도 앱이다 | ChatGPT 안의 모드다. 데스크톱 앱·웹·모바일에서 Work로 전환해 쓴다 |
| Work가 Chat보다 항상 낫다 | 짧은 질문, 간단한 문장 수정, 조언만 필요한 결정에는 Chat이 더 적합하다 |
| 결과물이 그럴듯하면 검증은 생략해도 된다 | 공식 문서는 "완성도 높은 답변도 불완전하거나 틀릴 수 있다"고 명시한다. 숫자·이름·날짜·인용은 직접 확인한다 |

세 번째 항목은 특히 중요하다. 공식 문서는 첫 결과를 "검사하고 반박하고 개선할 수 있는
초안"으로 대하라고 권한다. 법률·재무·의료·보안처럼 영향이 큰 판단에는 전문가 검토가
따로 필요하다.

## 정리

- ChatGPT Work는 ChatGPT 안의 모드이며, **완료 기준이 분명한 결과물**을 만들 때 쓴다.
- 대화가 목적이면 Chat, 결과물이 목적이면 Work, 개발자 세부가 필요하면 Codex다.
- 조사·파일·완성 파일·시각화·브라우저·코드·위임·반복·음성까지 아홉 가지 작업 유형을 다룬다.
- 2026년 7월 6~10일 주차에 발표됐고, 7월 9일 Codex 앱이 ChatGPT 데스크톱 앱에 통합됐다.
- 데스크톱은 모든 플랜, 웹·모바일은 Plus·Pro·Business·Enterprise·Edu에서 쓸 수 있으며
  실제 노출은 플랜·플랫폼·지역·롤아웃·워크스페이스 설정에 따라 달라진다.

다음 챕터에서는 ChatGPT를 어디서 받아 어떻게 Work로 전환하는지, 그리고 작업을 내 컴퓨터에서
돌릴지 클라우드에서 돌릴지 고르는 기준을 다룬다.
