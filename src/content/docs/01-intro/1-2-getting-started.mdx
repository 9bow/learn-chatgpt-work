## 같은 기능인데 화면이 다르다면

"동료가 보여 준 화면에 있던 버튼이 내 화면에는 없다." ChatGPT Work를 처음 쓸 때 가장
자주 겪는 상황이다. 원인은 대개 셋 중 하나다. 플랫폼이 다르거나(데스크톱 앱 대 웹),
작업 실행 위치가 다르거나(로컬 대 클라우드), 플랜·워크스페이스 설정이 다르다.

이 챕터는 그 세 가지 축을 정리한다. 어디서 시작하고, 어떻게 Work로 바꾸고, 작업을
어디서 돌릴지 고르는 기준까지 익히면 이후 챕터의 화면 설명이 훨씬 잘 들어맞는다.

## 어디서 시작하나

ChatGPT Work는 세 곳에서 쓸 수 있다. 각각 시작 절차가 조금씩 다르다.

**데스크톱 앱(macOS·Windows)** 이 가장 기능이 많다. 공식 문서의 순서는 이렇다.

1. `chatgpt.com/download` 에서 macOS 또는 Windows용 ChatGPT 데스크톱 앱을 설치한다.
2. 앱을 열고 ChatGPT 계정으로 로그인한다.
3. **작업 위치를 고른다.** 대화를 시작하거나, 프로젝트를 만들거나, 폴더를 연다. ChatGPT는
   내가 고른 위치의 파일과 컨텍스트를 쓸 수 있다.
4. **첫 메시지를 보낸다.** ChatGPT 또는 Codex를 고르고, ChatGPT에서는 입력창 위의
   토글로 Chat과 Work를 전환한다.

**웹**은 브라우저만 있으면 된다. `chatgpt.com` 에 로그인하고 **Work** 를 선택한다. 공식
문서는 리서치, 분석, 문서, 스프레드시트, 발표자료, Sites, 그 밖의 여러 단계 작업에는
Work를, 답변이나 대화에는 Chat을 고르라고 안내한다. 이어서 일회성 작업이면 대화를,
계속되는 업무면 프로젝트를 만들고 첫 메시지를 보낸다.

**모바일**에서도 Work를 쓸 수 있다. 클라우드에서 돌아가는 작업은 웹·모바일·데스크톱
사이에서 동기화되므로, 데스크톱에서 시작한 클라우드 작업을 휴대폰에서 이어 볼 수 있다.

```text
┌────────────────────────────────────────────────────┐
│               ChatGPT (하나의 계정)                │
└───────┬──────────────────┬─────────────────┬───────┘
        │                  │                 │
 ┌──────▼───────┐  ┌───────▼──────┐  ┌───────▼───────┐
 │  데스크톱 앱  │  │      웹      │  │    모바일     │
 │  macOS·Win   │  │   브라우저   │  │  iOS·Android  │
 ├──────────────┤  ├──────────────┤  ├───────────────┤
 │ 로컬 + 클라우드│  │   클라우드   │  │ Work · 이어받기│
 │   모든 플랜   │  │  Plus 이상   │  │   Plus 이상   │
 └──────────────┘  └──────────────┘  └───────────────┘
```

플랜 표기는 제품 페이지 기준이다. macOS·Windows 데스크톱은 모든 플랜, 웹과 모바일은
Plus·Pro·Business·Enterprise·Edu다.

전환 지점은 **입력창 위의 전환기(switcher)** 다. Chat과 Work를 오가는 토글이며,
데스크톱 앱에서는 먼저 ChatGPT와 Codex 중 하나를 고른 뒤 그 안에서 Chat과 Work를
전환한다.

2026년 7월 13~17일 주차 업데이트로 데스크톱 앱은 **Chat과 Work 대화를 ChatGPT 뷰 안에
함께** 보여 준다. 클라우드 Work 대화는 웹·모바일·데스크톱에서 동기화되고, 로컬 Work
대화는 내 컴퓨터에 남는다. ChatGPT 프로젝트도 데스크톱 앱에서 쓸 수 있다. Codex는
개발 워크플로용 전용 뷰와 별도 히스토리를 그대로 유지한다.

## 로컬에서 실행(Work locally)과 클라우드(Cloud)

여기가 데스크톱 앱만의 선택지다. 웹에서는 ChatGPT Work가 관리형 클라우드 환경에서
돌아간다. 데스크톱 앱에서는 입력창의 **Work locally** 라고 표시된 컨트롤을 열어
실행 위치를 고를 수 있다. **Cloud** 가 선택지로 보이면 둘 중 하나를 고른다.

| 구분 | 로컬에서 실행(Work locally) | 클라우드(Cloud) |
|---|---|---|
| 실행 위치 | 내 컴퓨터 | 격리된 호스팅 환경 |
| 쓸 수 있는 것 | 내 컴퓨터의 파일, 앱, 브라우저 | 업로드한 파일, 연결된 도구, 승인된 웹사이트 |
| 앱을 닫으면 | 작업이 함께 멈춘다 | 계속 진행된다 |
| 다른 기기에서 | 그 컴퓨터에 남는다 | 웹·모바일에서 이어받을 수 있다 |
| 가용성 | 계정 또는 워크스페이스에서 활성화된 경우 | 선택지로 표시될 때 |

고르는 기준은 단순하다.

- **내 컴퓨터의 파일이나 앱을 써야 하면 로컬에서 실행(Work locally)** 을 유지한다.
  다운로드 폴더의 엑셀 파일, 로컬에 설치된 프로그램, 내 브라우저 세션이 필요한 작업이
  여기 해당한다.
- **앱을 닫거나 컴퓨터를 껐는데도 계속 돌아가야 하면 클라우드(Cloud)** 를 고른다.
  휴대폰이나 웹에서 이어서 보고 싶을 때도 클라우드다.
- 공식 문서는 한 가지를 더 짚는다. **웹사이트를 주기적으로 조사하거나 확인하는
  예약 작업(scheduled tasks)에는 클라우드가 유용하다.** 실행이 내 컴퓨터가 깨어 있는지에
  달려 있지 않기 때문이다.

```text
                    ┌──────────────────────┐
    내 파일·앱 필요? │      YES      NO     │
                    └───┬──────────────┬───┘
                        │              │
              ┌─────────▼──────┐  ┌────▼─────────────┐
              │ Work locally   │  │ 앱을 닫아도 계속? │
              │ (로컬에서 실행)│  └────┬─────────┬───┘
              └────────────────┘   YES │      NO │
                                 ┌─────▼───┐ ┌──▼──────────┐
                                 │  Cloud  │ │ 둘 다 가능  │
                                 └─────────┘ └─────────────┘
```

진행 중에 ChatGPT는 스스로 진행 상황을 보여 주고, 정보나 승인이 필요하면 멈춘다.
결과가 큰 행동은 승인하기 전에 내용을 확인하고, 최종 결과는 쓰거나 공유하기 전에
검토한다.

## Windows에서 쓰기

Windows 지원은 2026년 3월 2~6일 주차에 시작됐다. 당시 Codex 앱이 Windows에 출시되면서
네이티브 PowerShell과 샌드박스 지원, 워크트리, 예약 작업(scheduled tasks), 스킬(skills)을
함께 제공했다. 리눅스 환경을 선호하는 개발자를 위해 WSL도 계속 쓸 수 있다. 이 기능들은
7월 9일 통합 이후 ChatGPT 데스크톱 앱 안에서 이어진다.

것은 **Windows에서도 로컬 실행이 가능하다**는 점이다.

## 여러 작업을 동시에 굴리기

Work의 진짜 이점은 작업 하나를 빨리 끝내는 데 있지 않고, **여러 작업을 동시에 걸어
두는 데** 있다. 데스크톱 앱은 사이드바에 프로젝트를, 본문에 대화를 나란히 보여 준다.

작업이 늘어나면 "무엇이 내 확인을 기다리는지"가 문제가 된다. 2026년 7월 27~31일 주차에
추가된 **Activity 뷰**가 이 문제를 다룬다. 최근에 주고받은 대화와 내 확인이 필요한 작업을
한곳에 모아 주며, 사이드바의 종 아이콘을 눌러 연다.

<ConceptCard title="로컬 프로젝트에 여러 폴더 넣기">

2026년 7월 20~24일 주차부터 데스크톱 앱의 로컬 프로젝트에 관련 폴더를 여러 개 넣을 수
있다. 새 대화와 자동 탐색의 기준이 되는 주 폴더(primary folder)를 하나 고르고, 나머지
폴더는 파일 검색과 읽기·편집에 쓰인다. 프로젝트 편집 화면에서 폴더를 추가한다.
개발 프로젝트에서 더 유용한 기능이지만, 문서 폴더가 여러 개로 나뉜 업무에도 쓸 수 있다.

## 해보기

실행 위치를 명시해 요청하면 결과가 훨씬 예측 가능해진다. 아래 두 프롬프트를 각각
로컬과 클라우드에서 시도해 보자.

**로컬에서 실행할 작업 — 내 컴퓨터의 파일을 쓴다.**

```text
[폴더 경로]에 있는 이번 달 정산 엑셀 파일 세 개를 열어 주세요.
계정 코드 기준으로 합쳐서 중복 행을 표시하고,
원본 파일은 수정하지 말고 정리본을 새 파일로 저장해 주세요.
저장한 경로와 무엇을 어떻게 확인했는지 알려 주세요.
```

**클라우드에서 실행할 작업 — 시간이 걸리고, 자리를 비워도 된다.**

```text
[경쟁사 3곳]의 공식 홈페이지와 요금 페이지를 확인해 주세요.
플랜 이름, 가격, 포함 한도를 표로 정리하고 각 항목의 출처 URL을 함께 적어 주세요.
확인할 수 없었던 항목은 추측하지 말고 "확인 불가"로 표시해 주세요.
작업이 끝나면 결과 요약을 먼저 보여 주세요.
```

두 프롬프트의 공통점은 **자료 위치, 하지 말아야 할 것, 완료 시 보고 방식**이 들어 있다는
점이다. 실행 위치만 바꾸는 것이 아니라 요청 내용도 실행 위치에 맞춰 쓰는 게 좋다.

## 정리

- 데스크톱 앱은 모든 플랜, 웹과 모바일은 Plus 이상 플랜에서 ChatGPT Work를 쓸 수 있다.
- 전환은 입력창의 Chat / Work 전환기에서 한다. 데스크톱에서는 ChatGPT와 Codex를 먼저 고른다.
- 내 컴퓨터의 파일·앱이 필요하면 **로컬에서 실행(Work locally)**, 자리를 비워도 계속
  돌아야 하거나 다른 기기에서 이어받아야 하면 **클라우드(Cloud)** 다.
- 예약 작업으로 웹을 주기적으로 확인하려면 클라우드가 적합하다.
- 확인이 필요한 대화는 사이드바의 종 아이콘, 즉 Activity 뷰에서 모아 본다.
- 여기 적힌 기능도 플랜·플랫폼·지역·롤아웃·워크스페이스 설정에 따라 보이지 않을 수 있다.

다음 챕터에서는 공식 문서가 권하는 첫 세 가지 작업을 실제 프롬프트와 함께 따라가 본다.
