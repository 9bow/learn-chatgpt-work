## 같은 설명을 네 번째 반복하고 있다면

"우리 팀은 마케팅이고, 보고 대상은 본부장이고, 문서는 항상 요약 먼저 쓰고, 숫자에는 출처를
붙여 달라." 이 문장을 이번 주에 몇 번 썼는지 세어 보자. 세 번 넘게 썼다면 그건 프롬프트에
있을 내용이 아니라 **설정에 있을 내용**이다.

공식 프롬프팅 문서의 원칙은 간단하다. 여러 대화에 걸쳐 적용되어야 하는 선호는
**Settings > Personalization**의 커스텀 지침에 넣고, 이번 대화에만 해당하는 내용은
프롬프트에 남긴다.

## 네 겹의 컨텍스트

개인화를 이해하는 가장 쉬운 방법은 적용 범위를 층으로 보는 것이다.

무엇을 어디에 두는지 헷갈릴 때 기준은 하나다. **반드시 항상 적용되어야 하는 규칙은
메모리에 의존하지 않는다.** 공식 문서는 메모리를 "도움이 되는 회상 계층"으로 보고, 항상
적용돼야 하는 규칙은 `AGENTS.md`나 저장소에 체크인된 프로젝트 문서에 두라고 명시한다.
메모리는 자동으로 쌓이는 성질 때문에 "이번에는 반영되지 않을 수도 있는" 계층이다.

| 넣을 곳 | 어울리는 내용 | 어울리지 않는 내용 |
|---|---|---|
| 커스텀 지침 | 응답 스타일, 말투, 기본 출력 형식 선호 | 특정 프로젝트에만 맞는 규칙 |
| 메모리 | 반복되는 업무 흐름, 안정적인 선호, 되풀이 설명 | 반드시 지켜져야 하는 규칙, 비밀 정보 |
| 프로젝트 지침 | 그 프로젝트의 용어·형식·검토 기준 | 개인 말투 선호 |
| 프롬프트 | 이번 요청의 결과물·자료·제약 | 매번 똑같이 반복되는 배경 설명 |

### 성격과 커스텀 지침

**Settings > Personalization**에서 기본 성격을 **Friendly**, **Pragmatic**, **None** 중에서
고른다. 성격은 ChatGPT가 **소통하는 방식**을 바꾸는 것이고, 모델이 할 수 있는 일을 바꾸지는
않는다. 이 구분은 문서에 명시되어 있다. 답변 품질이 아쉬워서 성격을 바꾸는 것은 효과가 없다.

커스텀 지침은 여러 대화에 걸쳐 따라야 할 선호를 담는다. 선호하는 응답 스타일이 대표적인
예다. Codex에서는 이런 개인 지침이 전역 `AGENTS.md` 파일에 저장되고, 프로젝트와 저장소도
각자의 지침을 제공할 수 있다.

화면에서 볼 것은 왼쪽 목록이다. 고정된 대화, 프로젝트, 최근 대화가 각각 다른 작업이고, 아래에
계정이 있다. 개인화 설정은 이 목록 전체에 적용되는 층이다. 컴포저 아래에는 3-2에서 다룬 권한
모드와 모델·지능 수준 선택이 함께 보인다. 문서 캡처 시점의 화면이므로 표기는 다를 수 있다.

## 메모리가 하는 일과 만들어지는 방식

메모리(memories)는 이전 작업의 쓸모 있는 컨텍스트를 이후 작업으로 이어 준다. 안정적인 선호,
되풀이되는 업무 흐름, 프로젝트 관례처럼 매번 다시 설명해야 했던 내용이 여기 들어간다.

먼저 두 종류를 구분해야 한다. **ChatGPT 웹은 ChatGPT 메모리를 쓰고, 로컬 Codex
클라이언트는 별도의 로컬 메모리 저장소와 제어를 쓴다.** ChatGPT Work는 계정과 워크스페이스에
제공되는 메모리 설정을 사용하며, 로컬 Codex 메모리 저장소나 로컬 메모리 제어를 쓰지 않는다.

로컬 메모리의 동작은 문서에 비교적 자세히 나와 있다.

여기서 실무적으로 중요한 성질은 **즉시 반영되지 않는다는 것**이다. 대화가 끝나자마자
메모리가 갱신되지 않고, 아직 진행 중인 작업을 요약하지 않으려고 충분히 유휴 상태가 될
때까지 기다린다. 방금 알려 준 내용이 다음 대화에 바로 나타나지 않는다면 정상이다.

저장 위치도 공개되어 있다. 로컬 메모리는 Codex 홈 디렉터리 아래에 저장되고 기본값은
`~/.codex`다. 주요 메모리 파일은 `~/.codex/memories/` 아래에 있고, 요약·지속 항목·최근
입력·근거 자료가 들어간다. 문서는 이 파일들을 **생성된 상태(generated state)** 로 취급하라고
안내한다. 문제를 진단하거나 디렉터리를 공유하기 전에 들여다보는 것은 괜찮지만, 손으로
편집하는 것을 주된 제어 수단으로 삼지는 말라는 뜻이다.

### 켜고 끄기, 그리고 대화 단위 제어

로컬 Codex 메모리는 **기본적으로 꺼져 있다.** 데스크톱 앱에서
**Settings > Personalization**을 열고 **Enable memories**를 켜야 한다.

대화 단위 제어도 있다. 데스크톱 앱에서 `/memories`를 입력하면 이번 대화가 기존 메모리를
쓸지, 그리고 이번 대화가 앞으로의 메모리 생성에 쓰일지 각각 정할 수 있다. 대화 단위 선택은
전역 설정을 바꾸지 않는다. 민감한 내용을 다루는 대화에서 이 제어를 쓰면 된다.

따라 다르다.

## Chronicle: 무엇이 옵트인인가

Chronicle은 정확하게 말하는 것이 중요한 기능이다. 문서의 표현을 그대로 옮기면 다음과 같다.

- **옵트인 리서치 프리뷰(opt-in research preview)** 다. 켜지 않으면 동작하지 않는다.
- **macOS의 ChatGPT Pro 구독자**에게만 제공된다.
- macOS **화면 기록(Screen Recording)과 손쉬운 사용(Accessibility) 권한**이 필요하다.
- 켜기 전에 프라이버시·보안·저장·사용 한도 관련 고려사항을 검토하라고 문서가 권한다.
- 언제든 일시정지하거나 끌 수 있다.

하는 일은 메모리를 **화면 컨텍스트로 보강**하는 것이다. 최근 화면 맥락을 메모리 생성에
활용해서, 지금 무엇을 하고 있었는지 매번 다시 설명하지 않아도 되게 한다. 다른 자료가 더
적합할 때는 Chronicle로 그 출처를 알아낸 다음, 실제 파일이나 문서를 직접 읽는 방식으로
동작한다.

켜는 순서도 정해져 있다. 데스크톱 앱 설정에서 **Personalization**으로 가서 **Memories**가
켜져 있는지 확인하고, Memories 설정 아래의 **Chronicle**을 켠 뒤, 동의 대화상자를 검토하고
**Continue**를 선택한다. 그다음 macOS 권한을 부여한다. 즉 **메모리가 꺼져 있으면 Chronicle은
쓸 수 없다.**

일시정지는 메뉴 바 아이콘에서 **Pause Chronicle** 또는 **Resume Chronicle**로 한다. 문서는
회의 전이나 남기고 싶지 않은 민감한 내용을 볼 때 일시정지하라고 권한다. 완전히 끄려면
**Settings > Personalization > Memories**로 돌아가 Chronicle을 끈다.

### 감수해야 하는 것

문서가 켜기 전에 알아야 한다고 명시한 위험은 세 가지다.

| 항목 | 내용 |
|---|---|
| 사용 한도 | 백그라운드에서 샌드박스 에이전트가 캡처 이미지로 메모리를 만들기 때문에 사용 한도를 빠르게 소비한다 |
| 프롬프트 인젝션 | 화면 내용을 통한 프롬프트 인젝션 위험이 커진다. 악성 지시가 담긴 사이트를 보면 그 지시를 따를 수 있다 |
| 저장 | 생성된 메모리는 기기에 **암호화되지 않은** 마크다운 파일로 저장된다 |

저장 경로와 수명도 공개되어 있다. 화면 캡처는 임시 파일이며 Chronicle이 실행 중일 때
`$TMPDIR/chronicle/screen_recording/` 아래에 나타날 수 있고, 6시간이 지난 캡처는 Chronicle이
실행 중일 때 삭제된다. 생성된 메모리는 `$CODEX_HOME/memories_extensions/chronicle/`
아래에 저장된다. 무언가를 잊게 하려면 해당 파일을 삭제하거나 마크다운을 편집해 지운다.
다만 문서는 **직접 새 정보를 추가하지는 말라**고 안내한다.

OpenAI로 무엇이 전달되는지도 문서에 나와 있다. Chronicle은 화면 맥락을 로컬에서 수집한 뒤,
주기적으로 임시 세션을 띄워 최근 활동을 메모리로 요약한다. 그 세션은 선택된 스크린샷 프레임,
스크린샷에서 추출한 OCR 텍스트, 시각 정보, 해당 시간 구간의 로컬 파일 경로를 처리할 수
있다. 메모리 생성에 쓰인 화면 캡처는 서버에서 처리되고, 처리 후에는 법적으로 요구되는 경우가
아니면 서버에 저장하지 않으며 학습에 사용하지 않는다. 생성된 메모리는 로컬에 저장되고, 이후
세션에서 컨텍스트로 포함될 수 있으며 ChatGPT 설정에서 허용한 경우 모델 개선에 쓰일 수 있다.

마이크와 시스템 오디오에는 접근하지 않는다. 그리고 문서는 **동의 없이 다른 사람과의 회의나
대화를 기록하는 데 쓰지 말라**고 명시한다.

## 해보기

커스텀 지침에 넣을 문장이다. 프롬프트가 아니라 설정 칸에 붙여 넣는다.

```text
나는 [직무]로 일하고, 보고 대상은 주로 [대상]이다.
문서를 만들 때는 다음을 기본으로 해 달라.
- 결론과 요청 사항을 맨 앞에 둔다
- 숫자에는 출처를 함께 표시하고, 확인되지 않은 값은 "미확인"으로 남긴다
- 발견 사실과 내 해석을 구분해 적는다
- 과장된 수식어는 쓰지 않는다
```

민감한 내용을 다루는 대화에서는 메모리를 대화 단위로 차단한다.

```text
/memories
이번 대화는 기존 메모리를 사용하지 않고,
앞으로의 메모리 생성에도 쓰지 않도록 설정해 달라.
```

메모리에 무엇이 남아 있는지 점검하고 싶을 때 쓰는 요청이다.

```text
지금 내 메모리에 어떤 내용이 들어 있는지 항목별로 정리해 달라.
그중 다음에 해당하는 항목이 있으면 따로 표시해 달라.
- 더 이상 맞지 않는 내용
- 특정 프로젝트에만 해당해서 전역에 두면 안 되는 내용
- 외부에 공유되면 곤란한 내용
```

## 주의점

- **비밀 값을 메모리에 남기지 않는다.** 문서는 생성된 메모리 필드에서 비밀 값을 마스킹한다고
  밝히지만, Codex 홈 디렉터리나 생성된 메모리 산출물을 공유하기 전에 직접 확인하라고
  권한다.
- **항상 지켜야 하는 규칙을 메모리에 맡기지 않는다.** 메모리는 즉시 갱신되지 않고 매번
  반영된다는 보장이 없다. 필수 규칙은 프로젝트 지침이나 체크인된 문서에 둔다.
- **Chronicle을 켠 채로 민감한 화면을 보지 않는다.** 회의 전이나 계약서·인사 자료를 볼 때는
  메뉴 바에서 일시정지한다.
- **암호화되지 않는다는 점을 팀과 공유한다.** 화면 캡처 임시 디렉터리와 메모리 디렉터리는
  컴퓨터의 다른 프로그램도 접근할 수 있다.
- **성격 설정으로 성능을 바꾸려 하지 않는다.** 소통 방식만 바뀐다.

## 정리

- 반복되는 배경 설명은 프롬프트에서 커스텀 지침으로 옮긴다.
- 메모리는 이전 작업의 컨텍스트를 이어 주지만, 즉시 갱신되지 않고 항상 반영되지도 않는다.
- 로컬 Codex 메모리는 기본적으로 꺼져 있고, EEA·영국·스위스에서도 기본 꺼짐 상태로 유지된다.
- 대화 단위로 메모리 사용과 생성을 각각 차단할 수 있다.
- Chronicle은 macOS ChatGPT Pro 대상 옵트인 리서치 프리뷰이며, 사용 한도 소비·프롬프트
  인젝션 위험·암호화되지 않은 로컬 저장을 감수해야 한다.
- 필수 규칙은 개인화가 아니라 프로젝트 지침이나 체크인된 문서에 둔다.

개인화가 "나"를 기준으로 컨텍스트를 관리하는 방법이라면, 다음 챕터는 "이 일"을 기준으로
컨텍스트를 묶는 방법이다. 프로젝트로 넘어간다.
