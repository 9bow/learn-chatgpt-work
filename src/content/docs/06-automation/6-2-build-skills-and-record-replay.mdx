## 만들기 전에: 어떤 일이 스킬이 되나

앞 챕터에서 스킬의 구조를 봤다. 이제 실제로 만든다. 출발점은 **이미 자주 하는 일**,
특히 일관성이 중요한 일이다. 월간 리포트, 정기 임원 보고, 규정을 지켜야 하는 요약이
대표적이다.

시작 전에 세 가지를 알고 있어야 한다.

- **입력(input)**: 사용자가 보통 무엇을 제공하는가. 파일, 링크, 맥락, 필드 값.
- **출력(output)**: 최종 결과물의 형식, 톤, 길이는 무엇인가.
- **가드레일(guardrails)**: 반드시 들어가야 하는 것과, 절대 일어나면 안 되는 것.

## 스킬의 세 가지 패턴

Academy는 실제로 만들어지는 스킬에서 반복되는 패턴 세 가지를 정리한다. 내 업무가
어디에 속하는지 먼저 정하면 SKILL.md를 쓰기 훨씬 쉽다.

| 패턴 | 핵심 | 예시 |
|---|---|---|
| 재사용 프로세스 (다단계 워크플로) | 순서가 중요하고, 정해진 플레이북을 따르는 것이 목표 | 규정 준수 보고, 재무 정합 로직, 여러 데이터 출처로 임원 보고서 작성 |
| 도구 기반 워크플로 | 특정 도구·시스템에서 정보를 안정적으로 가져오거나 결합하는 데 의존 | 통화 기록 도구에서 계정 인사이트 추출, 연결된 데이터 출처로 요약 생성 |
| 관례와 표준 | 내용이 바뀌어도 톤·형식·품질 기준을 일관되게 강제 | 스타일 가이드와 보조 자료로 블로그 초안 작성 |

**설계 팁이 하나 있다.** 스킬은 거대한 종단 간 스킬 하나보다 **섞어 쓸 수 있는
작은 빌딩 블록**으로 만들 때 대체로 잘 동작한다. 복잡한 워크플로라면 작은 스킬
여러 개로 쪼개는 편을 고려하세요. 예를 들어 "회의록 정리 + 액션 아이템 추출 +
주간 보고 작성"을 스킬 하나에 몰아넣기보다 세 개로 나누면, 회의록만 필요한 날에도
쓸 수 있다.

### 1) 반복 작업을 떠올린다

앞 절의 입력·출력·가드레일 세 가지를 채울 수 있는 작업을 고른다. 채울 수 없다면
아직 스킬로 만들 단계가 아니다. 먼저 두세 번 손으로 해 보고 절차를 확정하세요.

### 2) 지시를 적는다

스킬을 처음 만든다면 새 대화를 열고 **"Build me a skill…"** 로 시작하는 프롬프트를
쓰는 것이 가장 빠르다. ChatGPT Work에서는 `@skill-creator` 로 내장 생성기를 부를 수도
있다. 생성기는 이 스킬이 무엇을 하는지, 언제 촉발돼야 하는지, 지시만으로 갈지
스크립트를 포함할지 물어본다. 기본값은 지시만 쓰는 것이다.

좋은 지시 묶음에는 보통 다음이 들어간다.

1. 해결하려는 일(job-to-be-done)
2. 필요한 입력
3. 단계별 절차 (번호를 붙이면 좋다)
4. 요구되는 출력 형식 (예시 파일을 올리면 좋다)
5. 최종 품질 점검

ChatGPT 밖에서 직접 만들어 **업로드**할 수도 있다. 받아쓰기(dictation)로 워크플로를
말해서 초안을 빨리 만드는 것도 공식 팁으로 소개된다.

### 3) 검토하고 설치한다

ChatGPT가 스킬 초안을 만들고 설치 옵션을 제시한다. 초안을 읽고, 필요하면 지시를
다듬고, **Install** 을 선택해 워크스페이스에 추가한다. 이 단계를 건너뛰고 바로
설치하지 마세요. 초안에는 내가 말하지 않은 가정이 들어 있을 수 있다.

### 4) 일상 업무에서 쓴다

워크스페이스에서 활성화되면 ChatGPT가 관련 있을 때 자동으로 쓰거나, `@`로 직접
지목할 수 있다.

### 5) 공유하거나 개인용으로 둔다

워크스페이스 설정이 허용하면 스킬을 다른 사람과 공유하거나 대신 설치해 줄 수 있다.
단, **누가 스킬을 공유하고 설치할 수 있는지는 워크스페이스 소유자가 전적으로
통제한다.** 공유 버튼이 안 보이면 권한 문제일 가능성이 높다.

## SKILL.md 예시 세 개

앞의 세 패턴에 각각 대응하는 사무 업무용 초안이다. 그대로 쓰기보다, 우리 팀 형식에
맞게 항목을 바꿔 쓰세요.

### 재사용 프로세스: 회의록 정리

```markdown
---
name: meeting-notes-cleanup
description: 회의 녹취나 메모를 표준 회의록으로 정리할 때 사용. 결정 사항과 액션 아이템을 분리해야 할 때 촉발.
---

이 스킬은 흩어진 회의 메모를 결정·액션·미결로 분리한 표준 회의록으로 정리한다.

## 필요한 입력
- 회의 메모 또는 녹취록 (텍스트 또는 파일)
- 회의 제목, 날짜, 참석자 (없으면 물어본다)

## 절차
1. 내용을 결정 사항 / 액션 아이템 / 미결 질문 / 공유 정보로 분류한다.
2. 액션 아이템마다 담당자와 기한을 찾아 붙인다. 원문에 없으면 "미정"으로 둔다.
3. 결정 사항에는 그 근거가 된 발언이나 자료를 한 줄로 붙인다.
4. 서로 모순되는 발언이 있으면 양쪽을 모두 남기고 "확인 필요"로 표시한다.

## 출력 형식
- 머리말: 회의 제목 / 날짜 / 참석자 / 한 줄 요약
- 결정 사항: 번호 목록, 각 항목에 근거 한 줄
- 액션 아이템: 표 (내용 / 담당자 / 기한 / 상태)
- 미결 질문: 불릿
- 확인 필요: 불릿 (없으면 "없음"이라고 쓴다)

## 하지 말아야 할 것
- 원문에 없는 결정을 만들어 내지 않는다.
- 발언자를 추측해서 지정하지 않는다.

## 완료 전 점검
- 액션 아이템에 담당자 칸이 빈 곳이 없는지 확인한다.
- 결정 사항 개수와 근거 개수가 일치하는지 확인한다.
```

### 도구 기반: 주간 보고 자료 수집

```markdown
---
name: weekly-report-gather
description: 연결된 Slack과 Drive에서 주간 보고용 원자료를 모을 때 사용. 보고 작성 전에 촉발.
---

이 스킬은 연결된 도구에서 이번 주 원자료를 모아, 보고서 작성 전 단계의 정리표를 만든다.

## 필요한 입력
- 대상 프로젝트 이름
- 집계 기간 (기본값: 지난 7일)

## 절차
1. Slack의 해당 프로젝트 채널에서 기간 내 결정·이슈·요청을 뽑는다.
2. Drive의 해당 프로젝트 폴더에서 기간 내 생성·수정된 문서를 목록화한다.
3. 두 출처의 내용을 항목별로 대조해 중복을 합치고, 출처 링크를 모두 남긴다.
4. 지난주 정리표가 있으면 상태가 바뀐 항목을 표시한다.

## 출력 형식
- 표: 항목 / 출처(도구·링크) / 상태 / 지난주 대비 변화
- 출처가 하나뿐인 항목은 별도 섹션에 "교차 확인 필요"로 모은다

## 하지 말아야 할 것
- 도구에서 확인되지 않은 내용을 채우지 않는다.
- 어떤 메시지나 문서도 수정하거나 이동하지 않는다. 읽기만 한다.

## 완료 전 점검
- 모든 항목에 출처 링크가 있는지 확인한다.
- 기간 밖의 자료가 섞이지 않았는지 확인한다.
```

### 관례와 표준: 사내 공지 문체

```markdown
---
name: internal-announcement-style
description: 사내 공지·안내문을 우리 팀 표준 문체와 구조로 다듬을 때 사용. 초안이 이미 있을 때 촉발.
---

이 스킬은 초안을 사내 공지 표준 형식과 문체로 다듬는다. 내용을 새로 만들지 않는다.

## 필요한 입력
- 공지 초안
- 대상 독자 (전사 / 특정 부서 / 관리자)

## 문체 규칙
- 첫 문단에 무엇이 바뀌는지와 언제부터인지를 먼저 쓴다.
- 한 문장은 한 가지만 말한다. 40자 안쪽을 목표로 한다.
- 부서 내부 약어는 처음 나올 때 풀어 쓴다.
- 추측이나 미확정 사항은 "확정되면 다시 안내"로 명시한다.

## 출력 형식
1. 제목 (변경 대상 + 시점)
2. 요약 3줄
3. 무엇이 바뀌나
4. 나에게 미치는 영향
5. 해야 할 일 (없으면 "없음")
6. 문의 경로

## 하지 말아야 할 것
- 초안에 없는 일정이나 수치를 추가하지 않는다.
- 사과나 변명 문구를 임의로 넣지 않는다.

## 완료 전 점검
- 시점이 명시됐는지 확인한다.
- 독자가 해야 할 일이 한 문장으로 정리됐는지 확인한다.
```

세 예시의 공통 구조를 보세요. **필요한 입력 → 절차 → 출력 형식 → 하지 말아야 할
것 → 완료 전 점검**이다. 마지막 두 항목이 결과 품질을 크게 좌우한다.

## Record &amp; Replay: 설명하기 어려우면 보여 주기

절차를 글로 쓰기가 유난히 어려운 일이 있다. 클릭 위치, 필드 기본값, 어떤 화면에서
어떤 옵션을 고르는지 같은 것들이다. Record &amp; Replay는 **Mac에서 워크플로를 한 번
시연하고 그것을 재사용 가능한 스킬로 바꾼다.**

공식 문서가 드는 예시는 경비 처리, 주차 공간 예약, 올바르게 설정된 이슈 생성,
영상 게시, 정기 리포트 다운로드다. ChatGPT나 Codex는 그 패턴을 스킬로 포장해서,
이후 Computer Use, 브라우저 동작, 연결된 플러그인, 또는 이들의 조합으로 다시 쓰게 한다.

<ConceptCard title="가용성 제약을 먼저 확인하세요">
Record &amp; Replay의 현재 문서는 macOS 지원과 **Computer Use가 사용 가능하고 활성화돼
있어야 한다**는 조건을 명시한다. 과거 출시 안내의 지역 제외를 현재의 보편적인 제한으로
단정하지 말고 계정·조직의 제공 여부를 확인한다. 조직이 관리 설정으로 Computer Use를 껐다면
Record &amp; Replay도 함께 사용할 수 없다. 기능은 플랜·플랫폼·지역·롤아웃·워크스페이스
설정에 따라 다르므로, 메뉴에 안 보이면 이 조건들을 먼저 확인하세요.
</ConceptCard>

### 녹화하는 순서

1. 데스크톱 앱에서 ChatGPT를 선택하고 스위처에서 Work로 전환하거나 Codex를 선택한 뒤
   **Plugins** 를 연다.
2. **+** 메뉴를 연다.
3. **Record a skill** 을 선택한다.
4. 제안된 프롬프트를 검토하고, 도움이 될 맥락을 덧붙여 제출한다.
5. 대화가 동작 녹화 권한을 요청하면, 시연할 준비가 됐을 때 승인한다.
6. Mac에서 워크플로를 수행한다.
7. 끝나면 메뉴 바나 오버레이에서 녹화를 멈추거나, 대화에 끝났다고 말한다.

녹화 중 ChatGPT는 워크플로를 배우는 데 필요한 동작과 창 내용을 관찰한다. 멈출 때까지
계속되므로, 가르치려는 작업에만 집중해서 녹화하세요.

멈추면 ChatGPT가 포착한 워크플로를 검사해 스킬 초안을 만든다. 이 스킬에는 **언제
쓰는지, 어떤 입력이 필요한지, 어떤 단계를 따르는지, 결과를 어떻게 검증하는지**가
들어간다. 추가 수정을 요청할 수도 있다.

### 다시 실행하기

새 대화를 열고 생성된 스킬을 쓰라고 요청한다. 이번에 다른 값만 알려 주면 된다.
업로드할 파일, 만들 이슈, 리포트의 기간 같은 것들이다.

```text
@[녹화로 만든 스킬 이름] 을 써서 이번 달 [리포트 이름] 을 받아 주세요.
기간은 [시작일]부터 [종료일]까지입니다.
저장 위치는 [폴더 경로] 로 하고, 파일명은 스킬에 정의된 규칙을 그대로 지켜 주세요.
다운로드가 끝나면 파일 크기와 행 수를 알려 주고, 값이 비어 있는 열이 있으면 알려 주세요.
```

### 더 나은 녹화를 위한 팁

- 시연은 **짧고 완결되게** 한다.
- 녹화 시작 전에 목표와, 스킬을 쓸 때마다 달라질 수 있는 입력을 말해 둔다.
- 현실적인 입력을 쓰되 **비밀값과 민감한 데이터는 피한다.**
- 녹화 후에 스킬을 다듬어, 명명 규칙·필드 기본값·판단 지점처럼 겉으로 드러나지
  않는 선호를 명시한다.
- 워크플로가 끝나면 바로 멈춘다. 관련 없는 정리 작업까지 이어 가지 않는다.

## 스킬로 부족할 때는 플러그인

Record &amp; Replay는 시연한 워크플로를 스킬로 만드는 빠른 길이다. 하지만 팀 전체에
**안정된 별도 패키지를 배포**하거나, 여러 스킬을 묶거나, 커넥터를 포함하거나, MCP
서버를 추가하거나, 설치 메타데이터를 관리하려면 그 워크플로를 **플러그인으로
포장**하는 편이 맞다.

| 상황 | 알맞은 형태 |
|---|---|
| 나 혼자 쓰는 절차 고정 | 스킬 |
| 팀에 절차를 알려 주되 각자 설치 | 워크스페이스 공유 스킬 |
| 스킬 여러 개 + 커넥터를 한 묶음으로 배포 | 플러그인 |
| 클릭 순서까지 재현해야 하는 절차 | Record &amp; Replay로 만든 스킬 |

## 해보기

```text
"Build me a skill" 로 시작하겠습니다. 아래 업무를 스킬로 만들어 주세요.

해결할 일: [예: 매주 금요일 팀 주간 보고 초안 작성]
필요한 입력: [예: 팀원 업데이트 텍스트, 지난주 보고서]
절차: [1) ... 2) ... 3) ...]
출력 형식: [예: 요약 3줄 + 표(항목/상태/담당자/다음 단계) + 확인 필요 섹션]
반드시 지킬 것: [예: 원자료에 없는 내용 추가 금지]
절대 하지 말 것: [예: 담당자 임의 지정]

지시만 쓰는 스킬로 만들고, 스크립트는 넣지 마세요.
설치 전에 초안을 먼저 보여 주고, 제가 말하지 않아서 추측으로 채운 부분을 따로 알려 주세요.
```

마지막 두 줄이 중요하다. **추측으로 채운 부분을 밝히게 하면** 검토 단계에서
잘못된 가정을 걸러낼 수 있다.

## 정리

- 스킬 만들기는 반복 작업 고르기, 지시 작성, 검토·설치, 사용, 공유의 5단계다.
- 세 패턴(재사용 프로세스 / 도구 기반 / 관례와 표준) 중 어디인지 먼저 정한다.
- 작은 스킬 여러 개로 쪼개는 편이 거대한 스킬 하나보다 대체로 낫다.
- SKILL.md에는 입력·절차·출력 형식·금지 사항·완료 점검을 함께 적는다.
- 공유 권한은 워크스페이스 소유자가 통제하고, Record &amp; Replay는 macOS와 지역·
  Computer Use 조건이 붙는다.

스킬은 "어떻게"를 고정한다. 그런데 "언제"는 아직 사람이 챙겨야 한다. 다음 챕터에서
예약 작업(scheduled tasks)으로 실행 시점까지 넘기는 방법을 다룬다.
