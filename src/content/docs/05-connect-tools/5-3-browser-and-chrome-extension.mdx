## 왜 브라우저가 따로 필요한가

앞 챕터의 웹 검색은 공개된 페이지를 읽는 데 쓴다. 그런데 실무에서 필요한 화면은
대개 로그인 뒤에 있다. 사내 위키, CRM, 관리자 콘솔, 클릭을 몇 번 해야 나오는
리포트 화면이다. 검색으로는 여기에 닿지 못한다.

ChatGPT는 이 문제를 세 경로로 푼다. **내장 브라우저**는 ChatGPT 안에 별도로 들어 있는
브라우저이고, **브라우저 확장**은 내가 이미 쓰고 있는 브라우저의 탭을 쓰게 하는 방식이며,
**클라우드 브라우저**는 별도 실행 환경에서 웹 작업을 한다. 셋은 대체재가 아니라 권한과
로그인 상태가 다른 도구다.

| 구분 | 내장 브라우저 | 브라우저 확장 |
|---|---|---|
| 사용하는 프로필 | ChatGPT 전용 프로필 | 내 Chrome 프로필 |
| 내 열린 탭 | 공유하지 않는다 | 열린 탭을 맥락으로 쓸 수 있다 |
| 로그인 | 브라우저 안에서 직접 로그인 | 이미 로그인된 지원 브라우저 세션을 활용 |
| 화면을 함께 보기 | 대화 안에서 페이지를 같이 본다 | 페이지 옆에 사이드 채팅이 열린다 |
| 어울리는 일 | 만들고 있는 페이지 미리보기, 격리된 웹 작업 | 로그인이 필요한 사내 도구 작업 |

## 내장 브라우저: 화면을 함께 보기

데스크톱 앱의 내장 브라우저는 웹사이트와 로컬 웹 앱을 **대화 안에서 나와 ChatGPT가
함께 보는** 화면을 만든다. 페이지를 미리 보고, 시각적 피드백을 남기고, ChatGPT가
내 대신 사이트를 조작하게 할 수 있다. OpenAI 제품 페이지는 이 새로운 내장 브라우저
경험이 **여러 탭을 지원하고 더 풍부한 에이전틱 워크플로**를 가능하게 해서, 도구·파일·
계정을 넘나드는 작업을 쉽게 만든다고 설명한다.

여는 방법은 툴바에서 열기, URL 클릭, 직접 주소 입력, 그리고 단축키
`Cmd`+`Shift`+`B`(Windows는 `Ctrl`+`Shift`+`B`)다.

내장 브라우저는 **일반 브라우저와 분리된 프로필**을 쓴다. 내가 열어 둔 탭이나
세션을 자동으로 가져오지 않는다. 작업에 계정이 필요하면 그 안에서 직접
로그인한다. 브라우저 데이터와 프로필 가져오기 기능은 **Settings > Browser** 에서
관리한다. 다운로드는 기본적으로 시스템 다운로드 폴더로 가고, 같은 설정에서
위치를 바꾸거나 저장할 때마다 묻게 할 수 있다.

### 주소창에서 기록과 Google 검색

2026년 7월 마지막 주 업데이트로, 내장 브라우저 주소창에 입력을 시작하면 **자신의
방문 기록**에서 페이지를 찾아 준다. 일치하는 기록이 없으면 입력한 검색어로
**Google 검색**을 한다. 여기서 말하는 기록은 내장 브라우저의 자체 기록이며,
일반 Chrome 프로필이나 다른 브라우저의 페이지는 자동으로 포함되지 않는다.

같은 업데이트로 ChatGPT가 **지금 작업에 필요한 이전 맥락을 찾기 위해 방문
기록을 검색해도 되는지 물을 수** 있게 됐다. 이 요청은 가볍게 넘기면 안 된다.
방문 기록에는 사내 URL, 검색어, 그 밖의 민감한 정보가 들어 있을 수 있다.
작업에 그 맥락이 정말 필요할 때만 허용하세요.

### 페이지에 주석 달기

버그나 어색한 레이아웃이 렌더된 화면에서만 보일 때, 말로 설명하는 대신 그 위에
직접 표시하는 편이 정확하다.

1. **Annotation mode** 를 켠다.
2. 요소를 클릭하거나, 드래그해서 영역을 선택한다.
3. 코멘트를 쓰고 저장한다.
4. 대화에서 코멘트를 처리해 달라고 요청한다.

주석에서 **Adjust** 를 선택하면 폰트, 텍스트, 간격, 색 같은 값을 더 세밀하게
조정하고 결과를 페이지에서 미리 본 다음, 목표가 분명해진 상태로 주석을 보낼 수 있다.


### ChatGPT가 브라우저를 직접 조작하게 하기

내장 브라우저를 ChatGPT가 직접 운전하게 할 수도 있다. 플러그인 디렉터리에서
**Browser** 를 설치한 다음, 작업에서 브라우저를 쓰라고 하거나 `@Browser` 로
직접 지목한다. 이때 페이지를 열고, 클릭하고, 입력하고, 렌더된 상태를 확인하고,
스크린샷을 찍어 결과를 검증할 수 있다.

승인 구조는 두 겹이다. 첫째, 이미 허용한 사이트가 아니면 ChatGPT가 **그 사이트를
써도 되는지 먼저 묻는다**. 허용·차단 목록은 **Settings > Browser** 에서 관리한다.
둘째, 정보 제출·구매·권한 변경·데이터 삭제처럼 **민감한 동작 전에 다시 확인**한다.
내장 브라우저에서는 파일 업로드를 자동화하지 못한다는 제한도 있다.

한 가지 오해를 미리 정리하면, 사이트 접근 허용은 ChatGPT가 그 사이트와 상호작용해도
된다는 뜻일 뿐이다. **그 사이트의 내용이 신뢰할 수 있다는 뜻도, 모든 동작을 승인한
것도 아니다.** 페이지에 있는 지시문은 오해를 유발하거나 악의적일 수 있다.

## Chrome 확장: 이미 로그인된 브라우저를 쓰기

Chrome 확장은 ChatGPT가 내 Chrome을 조작하게 한다. 그래서 LinkedIn, Salesforce,
Gmail, 사내 도구처럼 **이미 로그인해 둔 사이트**를 읽거나 그 안에서 동작할 수 있다.

설치는 데스크톱 앱의 플러그인 디렉터리에서 **Chrome** 을 설치하고, 안내에 따라 확장을
설치하고 브라우저의 권한 요청을 승인한 뒤 사이드 채팅이 뜨는지 확인하는 순서다. 공식
브라우저 문서는 기존 Chrome, Edge, Brave, Opera, Vivaldi 탭에서 확장을 쓸 수 있다고
안내한다. 실제 지원 범위와 설치 경로는 플랫폼·배포 상태에 따라 확인한다.

쓰는 방법:

- Chrome 툴바나 **Extensions** 메뉴에서 ChatGPT를 열면 보고 있는 페이지 옆에
  사이드 채팅이 열린다. macOS에서는 `Cmd`+`Shift`+`.` 로도 열 수 있다.
- 패널은 그 탭에 붙어 있다. Chrome에서 시작한 대화는 ChatGPT 앱에서도 이어지고,
  앱의 최근 대화를 Chrome에서 열 수도 있다.
- **열린 탭을 멘션**해서 그 페이지를 맥락으로 쓰게 한다.
- 페이지에서 텍스트를 **드래그로 선택해 대화로 가져온다.** 전체를 복사하지 않고
  특정 문단만 물어볼 때 유용하다.
- 페이지에서 우클릭해 **Ask ChatGPT** 를 선택하면 관련 페이지 맥락과 함께 사이드
  채팅이 열린다.
- **YouTube 영상**을 열어 두고 사이드 채팅에서 물어보면, 자막이 있는 경우 타임스탬프가
  붙은 대본을 써서 설명·요약·질의응답을 한다.

### 여러 탭을 동시에

2026년 5월 4~8일 주차 업데이트로 Chrome 확장은 **브라우저를 가로채지 않고 백그라운드에서
여러 탭을 병렬로** 작업할 수 있게 됐다. 어떤 사이트를 쓸지는 내가 통제하므로, 조사와
데이터 입력과 검증을 한 작업 안에서 묶는 것이 실용적이 된다. 공식 예시 프롬프트를
옮기면 다음과 같다.

```text
열려 있는 제품 페이지들을 비교해서 플랜 제한을 표로 모으고,
각 항목의 출처 탭을 인용해 주세요.
수동 확인이 필요한 차이점은 따로 표시해 주세요.
```

사내 도구를 쓰는 예시다.

```text
@Chrome 으로 [CRM 이름] 을 열어 [고객사명] 계정을 찾고,
아래 통화 메모를 바탕으로 다음 액션과 다음 연락 예정일을 초안으로 정리해 주세요.
아직 저장하거나 전송하지 말고, 어떤 필드를 어떻게 바꿀지 먼저 보여 주세요.
메모: [통화 메모 붙여넣기]
```

두 번째 프롬프트가 왜 안전한지 보세요. **"아직 저장하지 말고 먼저 보여 달라"**
는 중단 지점을 넣었다. 로그인된 세션에서 동작하는 작업에는 이 문장을 습관처럼 붙이는
편이 좋다.

### 사이트 접근 승인 관리

기본값은 새 사이트마다 묻는 것이고, 물을 때 고를 수 있는 선택지는 네 가지다.

| 선택 | 의미 |
|---|---|
| Allow once | 이번 한 번만 이 사이트를 쓰게 한다 |
| Allow for this site | 이 사이트는 다시 묻지 않는다 |
| Allow for all sites | 어떤 사이트든 묻지 않는다. 위험이 높은 선택이다 |
| Decline | 이 사이트를 쓰지 못하게 한다 |

허용·차단 목록은 데스크톱 앱의 **Settings > Computer Use** 에서 Google Chrome 옆
**Manage** 로 관리한다. 허용 목록에서 도메인을 지우면 다음에 다시 묻고, 차단
목록에서 지우면 다시 물어볼 수 있는 상태로 돌아간다.

브라우저 기록 접근은 별도로 다뤄진다. 기록에는 사내 URL, 검색어, 로그인된 기기의
활동이 들어 있을 수 있어서, ChatGPT는 쓰려 할 때마다 묻고 그 요청 범위로만 접근한다.
**기록에는 항상 허용 옵션이 아예 없다.**

<ConceptCard title="OpenAI는 브라우징에서 무엇을 저장하나">
공식 문서에 따르면 OpenAI는 확장을 통한 Chrome 동작의 별도 전체 기록을 저장하지
않는다. 저장되는 것은 ChatGPT 맥락의 일부가 된 브라우저 활동, 즉 ChatGPT가 페이지에서
읽은 텍스트, 스크린샷, 도구 호출, 요약, 메시지 등 대화에 포함된 내용이다. 내 ChatGPT
데이터 관리 설정이 그 내용에 적용된다. 다만 비밀값이나 매우 민감한 데이터는 꼭 필요하고
내가 각 단계를 직접 검토할 수 있을 때가 아니면 브라우저 작업으로 보내지 마세요.
</ConceptCard>

## 웹에서 쓸 때는 다르다

데스크톱 앱이 아니라 웹의 ChatGPT Work에서는 **클라우드에서 동작하는 브라우저**를
쓴다. 내 기기의 브라우저와 분리돼 돌아가므로, 내 열린 탭이나 개인 브라우저 기록을
넘기지 않고 웹 작업을 맡길 수 있다. 다만 제약이 있다.

- 공개된, 로그아웃 상태의 웹사이트만 지원한다. 계정에 로그인하거나 자격 증명을
  요구하거나 내 브라우저의 로그인 세션을 쓸 수 없다.
- 자동화된 브라우저를 막거나 CAPTCHA를 요구하는 사이트에서는 작업을 끝내지 못할 수 있다.
- 내 열린 탭, 확장, 저장된 비밀번호, 로컬 브라우저 기록을 쓸 수 없다.
- 가용성은 플랜·워크스페이스 설정·롤아웃에 따라 다르다. Free와 Go를 제외한 유료
  플랜에서 모든 지역에 제공되며, Enterprise는 관리자가 워크스페이스에 켜야 한다.

## 개발자용 곁가지: Developer mode

Developer mode는 Chrome과 내장 브라우저의 Computer Use에서 동작하며, ChatGPT에
Chrome DevTools Protocol(CDP) 접근을 통제된 범위로 허용한다. JavaScript 성능
분석, 콘솔·네트워크 확인, DOM과 적용된 스타일 검사, 라이브 브라우저에서의 문제
진단에 쓴다. 비개발 직군이라면 "웹 화면 문제를 개발자가 더 깊게 파야 할 때 쓰는
스위치"로만 알아 두면 된다.

켜는 곳은 **Settings > Browser** 의 Developer mode에서 **Enable full CDP access**
다. 조직이 이 설정을 껐다면 개인이 켤 수 없다. 전체 CDP 접근은 민감한 브라우저
내부를 노출할 수 있어서, ChatGPT는 이 권한으로 사이트를 검사하기 전에 명시적 승인을
요구한다.

## 주의점

- **페이지 내용은 신뢰할 수 없는 맥락이다.** 사이트를 허용하기 전에 페이지를 검토하세요.
- **로그인된 세션은 나로 간주된다.** 사이트는 승인된 클릭, 폼 제출, 로그인 상태의
  동작을 내 계정에서 온 것으로 취급한다.
- **Allow for all sites는 마지막 선택지다.** 열려 있는 어떤 사이트든 ChatGPT가
  써도 된다고 신뢰할 때만 고르세요.
- **ChatGPT가 작업하는 동안 같은 Chrome을 쓰려면** 다른 브라우저를 쓰게 하는 편이 낫다.
- **가용성이 다르다.** 기능은 플랜·플랫폼·지역·롤아웃·워크스페이스 설정에 따라 다르다.
  내장 브라우저와 Chrome 확장은 데스크톱 앱 중심이고, 웹에서는 클라우드 브라우저로
  대체된다.

## 정리

- 내장 브라우저는 전용 프로필로 페이지를 함께 보고 주석을 남기는 데 쓴다.
- Chrome 확장은 이미 로그인된 내 Chrome을 써야 할 때 쓴다. 백그라운드 병렬 탭 작업이 된다.
- 주소창에서 방문 기록 검색과 Google 검색이 되고, 기록 접근은 매번 승인이 필요하다.
- 사이트 승인은 네 단계로 고르고, 민감한 동작은 별도로 다시 확인한다.
- 웹에서는 로그아웃 상태의 공개 사이트만 다루는 클라우드 브라우저가 쓰인다.

브라우저 밖의 데스크톱 앱, 예를 들어 사내 전용 클라이언트 프로그램은 어떻게 할까.
다음 챕터에서 Computer Use를 다룬다.
