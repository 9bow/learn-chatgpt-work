## 실행 중인 작업을 멈추지 않고 고치기

작업이 돌아가는 중에 빠뜨린 자료가 떠오른다. 또는 지금 만들고 있는 방향이 아니라는 걸
중간 결과를 보고 알아챈다. 이때 취소하고 처음부터 다시 요청하면 지금까지 모아 둔 컨텍스트가
버려진다.

ChatGPT는 실행 중에도 메시지를 받는다. 문제는 그 메시지를 **지금** 반영할지, **다음**
차례로 넘길지 정하는 것이다. 이 선택이 개입(steer)과 대기열(queue)이다.

## 개입과 대기열

공식 문서의 정의는 짧고 분명하다.

| 방식 | 동작 | 쓰는 상황 |
|---|---|---|
| 개입(steer) | 메시지를 **지금 실행 중인 턴**에 추가한다 | 방향을 바꾸거나, 빠진 정보를 넣거나, 새 소식을 알릴 때 |
| 대기열(queue) | 메시지를 **다음 실행**용으로 저장한다 | 지금 작업이 끝난 뒤에 해야 하는 후속 작업일 때 |

ChatGPT 데스크톱 앱에서는 **Settings > General > Follow-up behavior**에서 기본 동작을
고른다. 대기열에 들어간 메시지는 컴포저 위에 표시되고, 거기서 수정·순서 변경·즉시 전송·삭제를
할 수 있다. 같은 설정 화면에 기본값을 바꾸지 않고 이번 메시지만 다른 방식으로 보내는
단축키도 안내되어 있다.

판단은 간단하다. **지금 만들고 있는 결과물이 달라져야 하면 개입**, **결과물은 그대로 두고
그다음에 할 일이면 대기열**이다. 예를 들어 "예산 표는 3분기 기준으로 바꿔 달라"는 개입이고,
"이거 끝나면 같은 내용으로 메일 초안도 만들어 달라"는 대기열이다.

## ChatGPT가 먼저 멈춰 서는 경우

개입은 사용자가 먼저 끼어드는 것이고, 그 반대도 있다. ChatGPT가 스스로 멈춰 정보나 승인을
요구한다. 공식 문서는 두 가지 통제 장치가 함께 작동한다고 설명한다.

- **샌드박스(sandbox)**: 어떤 파일과 네트워크 자원에 접근할 수 있는지를 정한다.
- **승인(approvals)**: 어떤 행동 앞에서 멈춰 물어볼지를 정한다.

대부분의 작업에는 **Ask for approval**부터 쓰기를 권한다. 현재 작업 공간 안에서는 일하고,
그 경계를 넘으려 할 때 멈춘다. 검토자를 바꾸는 것이 접근 범위를 넓히지는 않는다는 점도
문서에 명시돼 있다. 예를 들어 **Approve for me**(설정에서는 Auto-review)는 경계 자체는
그대로 두고, 경계를 넘는 요청을 자동 검토로 보낸다.

데스크톱 앱을 처음 쓸 때 **Ask for approval** 외의 모드는 설정에서 켜야 목록에 나타난다.
모드를 켜는 것은 목록에 추가하는 것일 뿐이고, 진행 중인 대화의 모드를 바꾸지는 않는다.
조직 정책이나 로컬 설정에 따라 허용되지 않는 모드는 비활성 상태로 표시된다.

### 영향이 큰 행동은 프롬프트로 미리 막는다

승인 모드는 로컬 파일·명령·인터넷 접근 같은 실행 경계를 다룬다. 그런데 업무에서 실제로
곤란한 것은 대개 다른 종류다. 메일이 발송되고, 채널에 글이 올라가고, 여러 사람이 보는 문서가
수정되는 일이다.

공식 문서가 권하는 방식은 경계를 프롬프트에 적는 것이다. 문서에 예시로 나온 경계 문장은
이런 것들이다.

- 승인된 날짜와 예산 숫자는 바꾸지 말 것
- 제공된 자료만 쓸 것. 정보가 없으면 추측하지 말고 빠졌다고 표시할 것
- 권고안은 명시된 예산 범위 안에서 낼 것
- 메시지는 초안으로 준비하고 발송하지 말 것

경계는 한두 개만 쓰는 것이 좋다. 문서 표현대로 "ChatGPT가 밟는 모든 단계를 통제할 필요는
없다". 잘못 건드리면 결과물을 못 쓰게 되는 항목, 그리고 다른 사람에게 영향이 가기 전에
직접 확인해야 하는 항목에만 쓴다.

| 구분 | 어디서 정하나 | 예 |
|---|---|---|
| 실행 경계 | 컴포저 아래 권한 모드 | 작업 공간 밖 파일 접근, 명령 실행, 인터넷 사용 |
| 업무 경계 | 프롬프트에 쓴 문장 | 발송 금지, 확정 숫자 고정, 제공 자료만 사용 |
| 형식 경계 | 계획 승인 단계(3-1) | 결과물 형식과 분량, 중단 지점 |

## 말로 조종하기: 받아쓰기와 Voice

작업이 돌아가는 동안 방향을 바꾸려면 타이핑이 병목이 된다. 데스크톱 앱에는 두 가지 음성
경로가 있고, 둘은 서로 다른 기능이다.

  caption="말한 내용이 컴포저에 글로 들어온다. 보내기 전에 읽고 고칠 수 있다"
  source="https://learn.chatgpt.com/docs/features/voice"
/>

화면에서 볼 것은 음성이 곧바로 전송되지 않는다는 점이다. 말한 내용이 컴포저에 텍스트로
들어오고, 사용자가 읽고 고친 다음 보낸다. 데스크톱 앱에서 컴포저가 보이는 상태에서
`Ctrl`+`M`을 누른 채로 말하면 된다.

| 기능 | 무엇을 하나 | 언제 쓰나 |
|---|---|---|
| 음성 받아쓰기(voice dictation) | 말을 프롬프트 텍스트로 바꿔 컴포저에 넣는다 | 긴 지시를 빠르게 입력하고 보내기 전에 검토하고 싶을 때 |
| ChatGPT Voice | ChatGPT와 실시간으로 대화한다 | 진행 상황을 물어보고 말로 방향을 바꾸며 계속 일할 때 |

ChatGPT Voice는 GPT-Live를 기반으로 하고, 데스크톱 앱의 Chat·Work·Codex에서 아이디어를
정리하거나 작업을 조율하는 데 쓴다. 응답 중에 끼어들거나 후속 질문을 하거나 방향을 바꿀 수
있고, 작업이 시작된 뒤에도 계속 말하면서 진행 상황을 확인하거나 조종할 수 있다. 더 긴 작업은
별도 스레드로 시작해 두고, 진행·차단 요인·결과를 음성 대화로 다시 가져온다.

중요한 제약이 하나 있다. 대화나 작업은 **처음부터 음성 모드로 시작해야** ChatGPT Voice를
쓸 수 있다. 다른 모드로 시작한 대화에서는 음성 받아쓰기만 제공된다. 그리고 ChatGPT Voice는
자신이 지시하는 작업과 **동일한 권한 규칙**을 따른다. 말로 지시했다고 승인 절차가
생략되지는 않는다.

가용성도 확인해야 한다. ChatGPT Voice는 데스크톱 앱에서 Plus·Pro·Business·Edu·Enterprise
플랜에 제공되며, Enterprise와 Edu는 2주 얼리 액세스 기간을 거친 뒤 기본 제공된다. 기능은
플랜·플랫폼·지역·롤아웃·워크스페이스 설정에 따라 다르다.

## 해보기

실행 중인 작업에 끼어들어 방향을 바꾸는 개입 메시지다. 짧게 쓰는 것이 요령이다.

```text
잠깐, 방향을 하나 바꿔 달라.
지금 쓰고 있는 [문서명]에서 [항목]은 빼고, 대신 [다른 항목]을 넣어 달라.
지금까지 정리한 나머지 내용은 그대로 유지해 달라.
```

작업 시작 시점에 경계와 중단 지점을 함께 지정하는 프롬프트다.

```text
[대상]에게 보낼 [프로젝트명] 진행 상황 업데이트를 준비해 달라.
자료는 첨부한 회의록과 [연결된 도구]의 최근 업데이트만 쓴다.

경계:
- 확정된 날짜와 예산 숫자는 바꾸지 말아 달라
- 자료에 없는 내용은 추측하지 말고 "확인 필요"로 표시해 달라
- 초안까지만 만들고 발송하거나 게시하지 말아 달라

마치기 전에 모든 후속 항목에 담당자와 기한이 있는지 확인해 달라.
```

지금 작업이 끝난 뒤에 이어서 할 일은 대기열로 넘긴다.

```text
(대기열로) 위 문서가 완성되면, 같은 내용을 5줄 요약으로 줄여
[채널명]에 올릴 초안을 따로 만들어 달라. 올리지는 말아 달라.
```

## 주의점

- **개입 메시지를 길게 쓰지 않는다.** 실행 중인 턴에 붙는 지시이므로, 한두 문장으로 무엇을
  바꿀지만 말하는 편이 정확하다. 요구사항이 크게 바뀌면 차라리 새 요청으로 시작한다.
- **대기열을 쌓아 두고 방치하지 않는다.** 앞 작업 결과에 따라 필요 없어지는 후속 요청이
  생긴다. 컴포저 위 목록에서 수정하거나 지운다.
- **승인 요청을 습관적으로 통과시키지 않는다.** 특히 다른 사람이 보는 자료를 바꾸는 행동은
  요청 내용을 읽고 판단한다.
- **음성이 승인을 대신하지 않는다.** ChatGPT Voice로 지시한 작업도 같은 권한 규칙을 따른다.

## 정리

- 개입(steer)은 실행 중인 턴에 메시지를 추가하고, 대기열(queue)은 다음 실행으로 넘긴다.
- 기본 동작은 데스크톱 앱 **Settings > General > Follow-up behavior**에서 정한다.
- 샌드박스는 접근 범위를, 승인은 멈춤 시점을 정한다. 검토자를 바꿔도 범위는 넓어지지 않는다.
- 발송·게시·공유 문서 수정 같은 업무 경계는 프롬프트 문장으로 지정한다.
- 받아쓰기는 말을 프롬프트로 바꾸고, ChatGPT Voice는 실시간 대화로 작업을 조율한다.

여기까지는 몇 분에서 몇십 분 걸리는 작업을 다뤘다. 다음 챕터에서는 몇 시간에서 며칠까지
이어지는 작업을 Goal 모드와 알림으로 관리하는 방법을 본다.
